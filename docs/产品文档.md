# 政企部 AI 运营中心 · 产品文档

> 话术质量运营平台 —— 覆盖 SaaS/私有化规则版话术的巡检、优化、质检与关键词资产生产
> 版本：2026-11 · 服务端口 8787（前端构建产物由后端静态托管）

---

## 一、平台定位与总体架构

**解决什么问题**：政企 AI 外呼/呼入机器人的话术质量运营，过去依赖人工抽听通话、人工比对决策树，现在把「巡检 → 发现问题 → 生成优化素材 → 回归验证 → 交付」做成标准化流水线，并在同一平台沉淀正则库、质检规则等可复用资产。

**七大模块**（左侧导航，分组可折叠）：

| 模块 | 一句话定位 | 底层能力 |
|---|---|---|
| 巡检报告中心 | 面向客户的巡检报告生产（Word） | saas-xunjian-tongyong 等 skill |
| Saas规则版话术优化 | 云端规则版 bot 的巡检 + 待优化库生产 | DLC 取数 + CDP 话术包导出 + 巡检引擎 |
| 关键词生成 | 单句/批量的正则关键词资产生产 | zhengze-shengcheng skill（LLM） |
| 相似问泛化 | 知识库相似问批量泛化（全局唯一） | xiangshiwen-fanhua skill（LLM） |
| Agent质检 | 任意 bot 的通用质检 + 按天报告 + 飞书推送 | zhijian-all skill（规则注册制引擎） |
| Agent自动优化 | 证据驱动的 bot 优化测试（真实跑测） | voiceagent-evidence-driven-optimizer skill |
| 私有化规则版话术优化 | 私有化 bot 全量巡检 + badcase 正则优化 + 四件套 | siyouhua-xunjianyouhua skill |

**技术形态**：Vite + React 18 + Tailwind 4 前端；node:http + node:sqlite 后端（零外部依赖）；各模块调用本机已安装的 skill（Python 引擎 / CLI），任务串行队列执行（大任务不并发，防止拖垮服务）。

**统一交互模型**：所有模块都是「**提交任务 → 串行队列异步执行 → 任务库看进度/阶段 → 交付物下载**」。提交页只负责收集输入，执行进度全部在任务库/详情页可见，失败可读日志。

## 二、巡检报告中心

### 2.1 需求提交（/xj/submit）

面向客户交付场景的巡检报告（Word 文档）生产入口。

- **业务场景三选**：语音 SaaS / 文本场景 / 语音私有化，选场景后联动可用的巡检模板。
- **巡检模板**：每个模板绑定一个本地 skill 执行器（如 `saas-general` → saas-xunjian-tongyong）。执行器未接入的模板标注「执行器接入中」，不可提交。
- **表单字段**：租户名称（必填）、报告周期（起止日期，必填）、通话记录上传（拖拽多文件，xlsx/csv）。
- **提交后**：生成请求单据，spawn 本地 skill 的 Python 生成器，产出到输出目录，报告中心可下载。

### 2.2 报告提取（/xj/reports）

- **统计卡**：全部/制作中/已成功/失败 四个计数。
- **筛选与搜索**：按状态筛选（全部/制作中/已成功/失败），按租户、模板、周期模糊搜索。
- **操作**：下载已生成的 Word 报告；失败单可重试。

## 三、Saas规则版话术优化

云端 SaaS 租户的规则版 bot 巡检主链路。

### 3.1 任务提交（/）

提交表单只保留「平台取数」一种通话来源：

- **必填**：botId（数字）、companyId（数据租户号）。
- **可选**：botTenant、回看天数（默认近 30 天，1~90）、通话表（外呼 `dwd_call_call_instance_sh_di` / 呼入 `byrobotprod_inbound_instance_log_di`）、最小通话时长（过滤超短通话）。
- **提交后自动执行四阶段流水线**：

```
话术包导出（CDP 连星球后台，拉决策树/分支正则/知识库）
  → 通话取数（DLC 只读 SQL，按 company_id + robot_def_id + 时间窗分页拉全量）
  → 巡检（分支走向判定：分支正则命中 vs AI 实际去向）
  → 生成待优化库（问题问句 + 原正则 + 优化后正则）
```

- 取数阶段依赖本机钥匙串的腾讯云凭据（DLC 只读），凭据缺失时任务明确报错并给出录入指引。
- 数据取回后落 `calls.jsonl`（一通一行的标准对话格式），供后续所有模块复用。

### 3.2 任务库（/tasks）

- 任务列表：bot 名称/ID、状态徽标（排队/执行中/已完成/重试中）、当前阶段 + 进度条、待优化库产出条数、创建时间。
- 点击行进入**任务详情**：五阶段进度面板、KPI 卡（巡检通话数/问题数/待优化库条数）、待优化库表格（问题问句 · 原正则 · 优化后正则 · 来源库），支持 CSV 导出。
- 待优化条目可按来源库（垒土-分支正则库 / 垒土-问题正则库 / 知识库）过滤，可发起补词。

### 3.3 垒土-分支正则库 / 垒土-问题正则库（/libs/branch、/libs/question）

平台的两类正则资产库（当前基准来源：租户 67966 公安 SaaS 测试）：

- **垒土-分支正则库**：垒土节点分支引用的具名正则集合，巡检取词与补词建议的基准库。
- **垒土-问题正则库**：按用户问题语义组织的正则集合（标准问法 + 触发正则）。
- **功能**：分组名/标签搜索、查看每组正则条数、展开组内关键词明细；任务详情页补词时可选择写入的目标库。

## 四、关键词生成

### 4.1 单句 · 提交入口（/kw/single）

输入一句用户问句（如「我下载了这个app」），大模型生成：

- **15 条泛化问句**（同义改写，命中原句语义）
- **10 条规避案例**（形似但不应命中的句子）
- **1 条三段式正则**（左环视规避 + 核心词 + 右环视规避）

生成后本地即时验证：15/15 泛化全中 + 10/10 规避全不中才算通过（页面显示「验证 15/15 + 10/10 全通过」或具体未过项）。**所有内容可编辑**，编辑后可重跑验证，验证通过才建议采纳——宁可多改一遍，不交一条不可靠的正则。

### 4.2 单句 · 任务库（/kw/single/tasks）

历史生成任务列表，点进详情可回看问句、泛化/规避列表、正则与验证状态，可再次编辑重跑。

### 4.3 批量 · 提交入口（/kw/batch）

粘贴问句清单（每行一条）或上传 .txt/.csv/.xlsx/.jsonl，逐条走单句同款流水线（生成 → 验证），批次内串行执行。

### 4.4 批量 · 任务库（/kw/batch/tasks）

批次列表 → 批次详情（每条问句的生成/验证状态、通过率），失败条目可单独重跑。

## 五、相似问泛化

为知识库条目批量生成相似问（入口 /xs/new，清单 /xs/tasks）。

- **输入**：知识库表格上传（xlsx/csv/txt，含标准问列）、租户 ID、botId、业务场景（九大场景 + 其他，决定句式配比与俗称规范）、每条生成数量（精确到条）。
- **执行五步**（xsrunner）：

```
① 黑名单构建（标准问 + 线上已有 + 该 bot 历史任务产出全部并入）
② 场景规范加载（句式配比：确认问为主 + 俗称双轨 + 代问句式）
③ LLM 分批并行生成
④ 全局唯一性五项断言（撞黑名单/批内重复/语义重复等，撞车即剔除）
⑤ 三件套交付（相似问交付 xlsx / 导入模板 xlsx / 换行文本 txt）
```

- **核心纪律**：数量精确到条、全局唯一（同 bot 维度跨批次/跨任务/线上已有全部查重）、不编造价格/日期/证件。

## 六、Agent质检

通用 AI 通话质检（入口 /zj/new，问题清单 /zj/issues，任务库 /zj/tasks），底层是 zhijian-all 规则注册制引擎。

### 6.1 需求提交

- **通用质检规则主动展示**（侧栏面板）：10 条通用规则默认全部写入每一单——
  R01 AI沉默（红线）/ R02 输出内部流程或依据（红线）/ R03 口吻不符（红线）/ R04 超出知识范围联想生成（红线）/ R07 虚假处置或结果承诺（扣分）/ R08 未授权联系方式（红线）/ R11 输出Markdown（红线）/ R12 无效重复追问（扣分）/ R13 转人工未响应（扣分）/ R14 无依据未兜底（扣分）。
  规则设计遵循「宁可漏判不可误判」三铁律：放行守卫先于判罚（否定语境/正确否定/具体事实短回复/转写缺失一律放行）、证据可审计（每条判罚带原话+轮次）、推送前复核闸门。
- **提交字段**：botId（必填）、机器人名称（选填，自动从话术包/数据侧补齐）、大模型提示词全文 + 知识库表（xlsx/csv，二者至少一项——构成 R04 编造判定的事实依据库）、**自定义质检规则**（选填，最多 10 条：名称 + 触发正则 + 放行正则 + 红线/扣分 + 分值 + 判定说明；引擎动态生成规则文件挂入注册表）。
- **质检范围**：该 bot 近 7 天全部通话（平台取数，DLC 只读；也支持上传 xlsx/csv/jsonl 通话文件，列名别名兼容）。
- **执行管线**：话术包导出（bot/租户名补齐，失败不阻断）→ DLC 取数（按天打标）→ zhijian-all 引擎逐通质检 → 按天分组 → 生成按天 Word 报告 → **飞书推送**。

### 6.2 质检问题清单

按 **bot 维度汇总**质检发现的问题：每个已完成任务一行（不合格率/红线/均分/问题类型数），规则徽标展示（如 `R01 AI沉默不回复 · 7 通`）；点「查看」进入该任务详情，按规则分组展开**证据原话 + 轮次 + 判定说明**。

### 6.3 任务库

- 任务列表：bot 名称、状态徽标、阶段明细（话术包导出 → 取数 → 质检执行 → 报告生成 → 飞书推送）、进度条。
- 完成任务：**按天报告直链**（每天一行：`2026-11-26 99 通 · 不合格 2`，点击下载 Word）+ 飞书推送状态（已推送 N 天 / 失败天数 / 已关闭）。
- 详情页：五项 KPI（总量/合格/不合格/红线/均分）、按天报告下载、问题证据明细（可折叠）。

### 6.4 飞书推送（默认开启）

每个任务完成后**按天自动推送**到飞书群：先发 Word 报告附件，再发摘要文本（通话总量/合格/不合格率/红线/平均分/问题类型分布/问题通话记录 id 清单）。目标群在 `data/zj-config.json` 配置（feishuChatId / feishuChatName），默认「客户成功」；`feishuPush: false` 可整体关闭。单条消息超长自动分片，附件/文本双通道保证可达。

## 七、Agent自动优化

证据驱动的 bot 优化测试（入口 /ao/new，任务库 /ao/tasks，回归 /ao/regression），底层 voiceagent-evidence-driven-optimizer skill。

### 7.1 任务提交 · 两种模式

- **已外呼模式**：botId + 租户 ID → 从数仓拉历史通话，把真实质检问题作为优化证据输入。
- **未外呼（草稿）模式**：botId + 知识库/需求文档（可多份上传）→ 按知识拆解政策设计用例。

### 7.2 九步证据驱动流程

```
配置基线（星球 CLI export 开发态配置）
  → 问题输入（数仓/上传件/知识整理）
  → 政策台账（业务规则拆解）
  → 全面测试集（复现/边界/多轮/兜底用例设计）
  → 冻结（casebank lint + 语义审核 + freeze）
  → 真实跑测（独立会话逐案执行）
  → 逐案归因（PASS / FAIL / BLOCKED）
```

**边界**：任务只产出「基线 v0 + 逐案审核结论」；修复写入（prompt/知识变更）**需另行明确授权**，平台不自动改线上。

### 7.3 任务库 / 质检回归测试

- 任务库：八阶段进度（配置基线 → … → 逐案归因）、测试集条目明细、逐案审核结论表。
- **质检回归测试**：从质检问题（Agent质检产出）发起单案回归——LLM 生成该问题的复现用例 → lint/freeze → 真实跑测 → 逐案审核，用于验证一次话术修改是否真的修复了该问题且未引入新问题。

## 八、私有化规则版话术优化

私有化部署的规则版 bot 全量巡检 + badcase 正则优化一站式流程（入口 /sy/new，执行结果 /sy/tasks），底层 siyouhua-xunjianyouhua skill。

### 8.1 任务提交

- **输入**：通话记录上传（百应线索导出 zip/xlsx，或 jsonl；只落盘不解析，解析在任务管线内进行，错误可见可重试）+ botId。
- **可选夹具**：referenceBundle（已导出话术包 zip，跳过 CDP）、referenceSides（侧库目录）——用于离线/验收场景。

### 8.2 六阶段流水线

```
① import 通话导入（SAX 分片解析大文件 → calls.jsonl）
② bundle 话术包导出（CDP 或本地夹具，决策树/分支正则/知识库/变量）
③ engine 引擎构建（分支正则编译、侧库挂载）
④ audit 全量巡检（四类问题：分支命中错误/走默认未命中/知识库未命中/命中错误）
⑤ fix 正则优化（候选式设计 → V8 全量回归 → 误翻转=0 门槛 → 本地包落地）
⑥ deliver 四件套交付
```

**质量闸门**：正则改动必须通过全量回归且**误翻转 = 0**（原命中不得丢失、原未命中不得误中）才允许落包。

### 8.3 执行结果 · 四件套

任务完成后交付四件（详情页下载网格）：

1. **全量巡检问题表** xlsx（5 sheet：分支命中错误 / 分支走默认未命中 / 可补样本 / 优化方案汇总 / 巡检总览）
2. **正则改动汇总（分 bot）** xlsx（3 sheet：改动总览 / 每 bot 明细 / 验证口径）
3. **巡检报告** md
4. **修改明细** md（每条改动：✔采纳 / ✘否决 + 修改前后正则）

## 九、通用机制

### 9.1 任务队列

各模块独立串行队列（saas/sy/zj/ao 各一条）：同一时间只跑一个任务，CPU 密集的大任务不并发；服务重启后遗留的 running/queued 任务标记为失败（提示重新提交），不会出现僵尸任务。

### 9.2 数据口径与安全

- **DLC 取数**：只读 SQL（仅 SELECT/WITH），表级授权清单写死在代码里，凭据走本机 macOS 钥匙串，不落盘不进代码。
- **话术包导出**：CDP 连接星球后台页签拉取（用户本地登录态）；私有化模式支持本地夹具离线执行。
- **通话记录**：上传原始文件只落盘（`data/uploads/`），解析一律放任务管线（日志可见、失败可重试），避免大文件解析阻塞请求进程。

### 9.3 目录约定

```
data/
  tasks/<id>/calls.jsonl      saas 巡检通话
  sy-tasks/<id>/              私有化任务（bundle/巡检/四件套）
  zj-tasks/<id>/              Agent质检（inspect.json / issues.json / 按天报告 docx）
  zj-config.json              Agent质检配置（飞书群 / 推送开关）
  uploads/                    上传原始文件
```

### 9.4 页面骨架与设计语言

所有页面统一 `page-header`（eyebrow 眉题 + 20px 标题 + 13px 说明）+ `card` 白卡 + sticky 表头 + 斑马纹；状态徽标统一四色（排队灰/执行中蓝/成功绿/失败红）；侧边栏 11px 大写分组标签 + 12.5px 二级项 + 激活态左色条，分组可折叠。

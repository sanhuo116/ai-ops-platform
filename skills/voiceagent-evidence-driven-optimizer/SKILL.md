# VoiceAgent 证据驱动优化

目标：形成“真实来源 → 问题归因 → 自洽验收 → 真实测试 → 最小修改 → 全量回归”的可审计闭环。内置星球 CLI 与系统凭据数仓适配，无须另装旧技能；业务入口 **BOTID**，不要求租户 ID。

## 启动

先确认目标BOT、允许修改的环境、历史绝对时间窗和客户反馈来源。用户只给BOTID时，先读取当前开发态并归档，不编造历史源BOT或政策。测试副本无通话时，从用户给定通话ID反查实际BOT并记录映射；来源BOT只读，不能把同租户全部BOT当作目标。

安装与登录见 [install.md](references/install.md)，操作见 [cli.md](references/cli.md)。所有脚本相对本技能目录执行。未授权修改时继续读取、分析、测试与生成计划；已有明确授权则按范围执行，不重复询问。

## 项目流程

1. **建立工作区和配置基线。** CLI export 读取全局 Prompt、各节点/版本、知识原文/相似问、模型、变量、动作与运营设置。运行 `analyze.py inventory` 建立索引；人工/Agent继续阅读全文。明确 unresolved 与不支持的流程，不把导出数量当成召回证明。
2. **整理问题输入与历史事实。** 阅读 [数据与反馈](references/data.md)，用 `warehouse.py plan/fetch` 在授权范围取数。呼入：元数据表加日志表；外呼：含content的外呼表，每BOT每天最多2000通。对账COUNT、下载量、唯一ID、无正文、空文本、序号缺口；候选异常与确认错误分开。反馈表、截图、通话ID分别留证，不能读清的标待核实。
3. **逐条拆解当前业务规则。** 阅读 [拆解与用例设计](references/case-design.md)。建立政策台账：主体、对象、时点、条件、结论、例外、证件材料、动作、完整原文位置。对冲突源建立待确认项，不能强造唯一政策。所有黄金答案来自本次真实配置及用户确认的口径，不由常识或历史机器人回答生成。
4. **构建全面且合理的测试集。** 合并客户反馈复现、历史高频/风险、每个知识条目、条件边界、多轮上下文、真实动作、幻觉诱导及无依据兜底。为每案写最小充分验收和禁止错误，逐条做冲突审查；记录覆盖矩阵与缺口。全面以业务规则和风险覆盖衡量，用例规模根据实际BOT确定。示例模板见 assets，必须替换为实际证据。
5. **冻结并执行基线。** 按 [evaluation.md](references/evaluation.md) 完成 lint、显式语义审核、freeze、真实全量 run。每案独立会话，保留每轮输入、回复、原始事件、工具回执、未答/未发轮与前后资源指纹。
6. **逐案审核并归因。** 完整阅读回复和源文，再记录 PASS/FAIL/BLOCKED。不能以关键词打分代替政策审核；漏读括号例外造成的误判也要修正并保留历史。转人工必须核对触发条件与真实工具，不能只看“为您转接”。传输错误与语义错误分开，不重试语义FAIL挑答案。
7. **提出并执行最小修复。** 优先修复确认的政策错误、条件丢失、错误转接、虚构承诺与流程失控。Prompt写清优先级、主体绑定、条件缺失澄清、禁止补政策和真实动作；知识保留完整例外。一次逻辑修改明确解决的问题、证据、差异和还原路径。使用 CLI plan 和 `iteration.py` 写开发态，当前完整基线必须已执行并审核；保留模型、工具运营参数等非目标配置。
8. **每轮完整回归。** 每次修改后新目录运行全部冻结用例，逐案审核。新增知识另加标准问；主集与新增问均通过后，对高风险表述重复稳定性测试。所有组必须绑定同一资源。若还需修改，重新全量，不用只复测失败案代替。
9. **验收与交付。** 最终全PASS、无BLOCKED、资源稳定才称“本测试集通过”。保留完整来源、政策台账、反馈映射、用例修订记录、版本计划/回执、每轮结果和现状说明。开发态验收不自动发布，语音/ASR/SIP现场验收单独列明。报告结构见 [交付与验收](references/delivery.md)。

## 停止与恢复

- 源文冲突：冻结矛盾结论的修改，保留“核实/澄清”方案，继续不受影响部分。
- 资源漂移、目标不符、回读不一致、写入结果不确定：停止后续写入，先独立读取确认；不盲重试创建或覆盖。
- 连续传输异常：保存错误/partial并暂停该批；同资源、同bank、同变量可显式resume，保留已完成回复。
- 多轮仍失败时按证据判断检索/知识/Prompt/模型/平台或用例问题，提出最小下一验证。不得为了全PASS放宽正确政策、伪造动作、删除失败案或无限重试。

## 当前实现边界

内置 CLI 支持开发态 Prompt 和既有普通文本 FAQ 的计划、写入、回读及回滚；知识新建、特殊动作知识、人工录音和复杂富文本需专项适配。Agent负责语义拆解、案例设计、源文审查和逐案判断，脚本负责确定性执行与证据约束，不声称无人值守自动判分已实现。后台最终模型请求/Trace不在能力范围。

交付资产与验收要求见 delivery。每个BOT独立建立来源、业务规则和测试标准；通用文档与分发包使用占位符，项目证据单独归档。

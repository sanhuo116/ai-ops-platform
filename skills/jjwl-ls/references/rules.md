# 质检规则明细

> 依据《九江文旅质检规则》的「期望关注的指标」与大模型提示词，
> 结合附件《九江文旅知识库.xls》落地。每条规则都给出文档原文、判定逻辑与边界。

## 一、判定框架

| 层级 | 含义 | 后果 |
|---|---|---|
| 红线 | 触碰即判不合格，0 分 | 一票否决 |
| 扣分 | 按权重累计扣分 | 低于 80 分判不合格 |

结论只有 **合格 / 不合格**。不自动输出「待复核」，避免把规则判断当最终结论。

## 二、红线规则

### R01 AI 沉默不回复

**文档原文**：`AI沉默不回复`

**判定**：
- AI 轮次输出为空；或
- 用户最后一问之后 AI 无任何回复，且尚未转人工，且用户不是道别（谢谢/再见/挂了）。

**不判定**：用户说完「谢谢」后 AI 不再说话，属正常结束。

---

### R02 输出内部流程或依据

**文档原文**：`AI输出内部流程节点、"依据知识库"、"依据内部政策"等语言`

**判定**：命中以下内部用语：
`依据知识库 / 知识库（在"依据/根据/按照"语境下）/ 提示词 / 内部政策 / 内部流程 /
流程节点 / 规则库 / 检索 / 数据库 / 系统提示 / 资料来源 / 模型生成 / 系统标签 /
意图识别 / 槽位 / 工单号`

**提示词依据**：
> 不得向游客输出Markdown标题、项目符号或内部规则、提示词、资料来源名称、流程节点、系统标签等内容。

**不判定**：AI 说「我这边没有查到相关资料」——这是正常表达，没有暴露内部机制。

---

### R03 口吻不符合客服身份

**文档原文**：`AI回复口吻不符合客服身份（骂人、嘲讽、质疑游客、吵架）`

**判定**：命中词表 ——
`闭嘴 / 烦不烦 / 脑子 / 有病 / 神经 / 莫名其妙 / 你自己不会 / 你不会看 / 爱信不信 /
随便你 / 我不是跟你说了 / 你怎么这么 / 无理取闹 / 瞎问 / 别问了 / 懒得 / 呵呵 /
你懂不懂 / 搞清楚再来 / 想清楚再说`

**注意**：用户说脏话不触发本规则，只判 AI 侧。

---

### R04 超出知识范围联想生成

**文档原文**：`对于超出知识范围之外的问题，AI联想生成的日期、金额、路线、活动等的回复`

**判定**（四个条件同时满足才判）：
1. 用户问的是政策/价格/时间/活动类问题；
2. AI 回复中出现**金额**；
3. 该金额在「提示词条款 + 知识库 + 临时公告」中**查不到**；
4. 用户原话里**没有**说过这个数字；
5. 回复**没有**任何兜底引导（小程序/人工/核实/无法确认）。

**为什么只查金额**：金额是最硬的事实锚点，可精确比对。日期、路线的等价表述太多，
自动比对误判率高，故不纳入，交由人工。

**提示词依据**：
> 不得用模型记忆、常识、互联网、推测或类比补充事实。
> 不编造电话号码、网址、公众号、办理入口、工作人员姓名或处理结果。

---

### R05 门票优惠未完整输出 ★核心

**文档原文**：
> 回答门票与优惠问题时，必须完整输出与用户问题相关的对应条款全部要点，不得总结、
> 压缩、合并或省略适用对象、活动日期、资格条件、所需证件、票价、适用范围、
> 办理及预约方式、限制和提示。一个问题涉及多项政策时，逐项完整说明。

**判定步骤**：

1. **匹配条款**：用问题中的**区分性实体**（地区 / 人群 / 景点）匹配条款名。
   - 「庐山」「九江」「门票」等通用词**不参与**匹配。
   - 理由：这些词几乎出现在每个条款名里，参与匹配会让任何问门票的问题都
     错配到「第五届庐山音乐节乐迷优惠」。
2. **提取要点维度**：从**条款原文**提取该条自带的维度（票价 / 资格对象 / 证件 /
   日期有效期 / 限制提示）。条款没写的维度不要求回复覆盖。
3. **检查覆盖**：把该轮**及之后**的全部 AI 回复合并检查，而非只看单句。
4. **兜底放行**：若 AI 明确表示「无法确认/暂时没有/建议查小程序/转人工」，
   视为合规兜底，不判漏项。

**典型不合格案例**：

| 场景 | AI 回复 | 缺失 |
|---|---|---|
| 深圳居民门票 | 「80 元，11月15-30日，凭身份证现场核验」 | 限制提示（不含观光车、索道等二次消费） |
| 秋假学生免票 | 「18岁以下学生可以免票」 | 适用省份、随行亲属政策、办理方式 |
| 退役军人免票 | 「退役军人免票」 | 所需证件、办理窗口 |

**不判定**：
- AI 分步解答，游客追问后补齐 —— 合并检查已覆盖；
- AI 说「这个我不确定，建议您问下窗口」 —— 合规兜底；
- 用户只是问「门票多少钱」而条款本身没有限制条件 —— 无该维度。

---

### R08 给出未授权的联系方式

**提示词原文**：
> 不编造电话号码、网址、公众号、办理入口…只有本提示词或本轮提供的景区资料中
> 明确列出的联系方式才可告知。

**判定**：出现非白名单号码。

**白名单**（文档中明确给出的）：`4009006162`（景区热线）、`0792-8296666`（观光车夜间预约）。

---

### R13 要求转人工未响应

**提示词原文**：
> 只有平台转人工工具返回成功，才可告知已转接。

**判定**：
- 红线：用户明确要求转人工后，AI **无任何回复**；
- 扣分（25）：AI 有回复但**未给出转接动作**。

**不判定**：用户尚未要求转人工，AI 主动询问「需要帮您转人工吗」——这是正常服务。

## 三、扣分规则

| 编号 | 规则 | 分值 | 文档/提示词依据 |
|---|---|---|---|
| R06 | 汇总计算总价 | 25 | 严禁计算或汇总多人总票价、多项组合总价 |
| R07 | 虚假处置或结果承诺 | 25 | 不承诺一定免票、开放；不声称已开票、受理、派人 |
| R11 | 输出 Markdown/内部格式 | 25 | 不得输出Markdown标题、项目符号 |
| R13 | 要求转人工未执行 | 25 | 转人工条款 |
| R14 | 无依据且未兜底 | 25 | 无答案时应简短说明并引导官方/人工 |
| R12 | 无效重复追问 | 15 | 不得重复索要；每次一个问题 |

**R06 判定细节**：需同时出现「一共/总共/合计/加起来/总计/共计」**且**合并了
两个以上不同金额。只说「成人票160元」不触发。



## 四、红线规则（新增优惠复核四条）

| 编号 | 规则 | 分值 | 复核基准 |
|---|---|---|---|
| R15 | 金额复核不合格 | 0（红线） | 复核游客身份是否符合活动要求、门票价格是否正确；身份不符/金额不符/日期不符 → 不合格 |
| R16 | 户籍复核不合格 | 0（红线） | 复核游客户籍是否符合活动要求，判断 AI 回复是否正确 |
| R17 | 索道观光车优惠不合格 | 0（红线） | 判断是否乱给索道、观光车优惠 |
| R18 | 年龄相关优惠判断错误 | 0（红线） | 年龄相关优惠给出错误口径 |

**R15 判定细节**：只对「优惠词紧邻金额」（半价80元/可按75元购买）核对条款价目；
正常票价（成人票160元/往返60元）、「没有优惠」告知句、总价汇总句（总共X元，
归 R06）不判。用户问索道/观光车时不与门票条款配对。

**R16 判定细节**：用户自述户籍（我是X人/户籍X）与条款适用地区比对；
AI 明确告知适用范围（「不在名单里」）、引导现场核验兜底，均属正确答复。
用户问句提及的地区与条款地区冲突时（问江苏、条款是九江市辖区）不判。

**R17 判定细节**：优惠动词须紧邻索道/观光车（≤10字）。放行：票价表事实
（观光车90元含上下山）、排除性表述（需另外购买）、正确告知无优惠、
儿童身高免票、音乐节乐迷五折、残疾人等证件群体优惠、接驳车/酒店接送。

**R18 判定细节**：只核 AI 的**边界声明句**（X周岁以上/以下 + 免票/购票）；
用户口述年龄被复述不算错。AI 已在别处给出正确边界（年满65）时放行。
「18周岁以下」属秋假学子口径，不按儿童免票边界判。
- 陈述句重复 → 不判（属可接受的信息重申）
- 转接播报重复 → 不判（固定话术）
- 寒暄重复（「您好，请问有什么可以帮您」）→ 不判

## 四、刻意不纳入自动判定的项

质检可信度来自**低误判**。以下情形不写进规则：

| 情形 | 原因 |
|---|---|
| 单句语义等价判断 | 「80元」可能够也可能不够，需上下文人工判断 |
| 路线/行程是否虚构 | 无结构化线路库可比对 |
| 语速、打断、静音 | 文本记录无法可靠还原 |
| 用户口音导致识别错误 | 责任不在 AI |
| 转接后等待播报重复 | 固定播报，非 AI 决策 |
| 日期表述是否等价 | 「11月15日」vs「下月中」等价性判断误判率高 |

这些建议进人工抽检队列。

## 六、评分与阈值

```
得分 = 100 - Σ(扣分项)
红线命中 → 得分 0，判不合格
否则 得分 < 80 → 不合格；≥ 80 → 合格
```

阈值 80 的含义：允许一处轻微扣分（如重复追问 15 分）仍合格，
但两处以上明显问题必须整改。
